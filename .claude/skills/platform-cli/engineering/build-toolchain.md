# CLI Engineering — Build Toolchain

## Node/TypeScript CLI

**Preferred bundler:** esbuild (fast, single-file output)
**Alternative:** tsup (wraps esbuild, dual ESM+CJS output)

**package.json requirements:**
```json
{
  "bin": { "<tool>": "./dist/cli.js" },
  "files": ["dist/"],
  "engines": { "node": ">=18" }
}
```

**Shebang:** `#!/usr/bin/env node` must be first line of compiled entry point.

**Permissions:** `chmod +x dist/cli.js` must be part of build step.

**Single-file output:** Preferred. Bundle all dependencies into one file for reliability. Exception: native `.node` addons (declare explicitly).

**Postinstall scripts:** Prohibited. No arbitrary code execution at install time.

**Peer dependencies:** Declared as `dependencies`, not `peerDependencies` — CLI users install the tool, not a library.

---

## Python CLI

**Packaging:** `pyproject.toml` (PEP 621). No `setup.py`.

**Entry point declaration:**
```toml
[project.scripts]
<tool> = "<package>.__main__:main"
```

**Distribution:** PyPI via `python -m build` + `twine upload`. Build artifacts: sdist + wheel.

**Binary option:** PyInstaller or Nuitka for single-binary distribution. Declare if used — adds significant build complexity.

**Version:** `importlib.metadata.version("<package>")` — not hardcoded in source.

---

## Go CLI

**Build:** Standard `go build`. Makefile for cross-compile targets.

**Single binary:** Default output. No runtime dependencies. Target triples declared in Makefile:
```makefile
PLATFORMS := linux/amd64 linux/arm64 darwin/amd64 darwin/arm64 windows/amd64
```

**Versioning:** Inject via `-ldflags`:
```
go build -ldflags "-X main.version=$(VERSION)" ./cmd/<tool>
```

**go.sum:** Committed. Reproducible builds require pinned checksums.

**CGO:** Disabled by default (`CGO_ENABLED=0`) for maximum portability. Enable only with explicit justification.

---

## Rust CLI

**Build:** `cargo build --release`. No debug builds for distribution.

**Single binary:** Default. Strip symbols for size: `cargo build --release --strip` (or via Cargo.toml `[profile.release]`).

**Cross-compilation:** `cross` crate for multi-platform builds. Target triples declared in `.cargo/config.toml`.

**cargo-dist:** Recommended for release automation and GitHub Releases publishing.

**Cargo.lock:** Committed for binaries (gitignored for libraries — this is a binary).

## Distribution Channels

### npm global
```
npm publish
npm install -g <tool>
```
- `npm pack` smoke test before publish
- Verify `npm info <tool>` before tagging as released
- Tag: `npm publish --tag latest` only after smoke test passes

### PyPI
```
python -m build
twine check dist/*
twine upload dist/*
```
- Test via `pip install --dry-run` equivalent before publish
- TestPyPI smoke test required for first publish

### Homebrew tap
- `Formula/<tool>.rb` in tap repository
- Formula must specify `sha256` of each release tarball — not a branch reference
- `brew test <tool>` must pass

### GitHub Releases (binary)
- Release tagged in git before upload
- Checksums file (`SHA256SUMS`) uploaded alongside binaries
- Platform matrix: linux-amd64, linux-arm64, darwin-amd64, darwin-arm64, windows-amd64 (at minimum)

## Shell Completions (if declared)

**Generation:** Completions generated by the tool itself (`<tool> completion bash`, `zsh`, `fish`).

**Installation instructions:** Documented in README. Not auto-installed by postinstall.

**Testing:** Run generated completion file through shell parser (`bash -n`, `zsh --no-exec`) — verify no syntax errors.

## CI Build Gates

Before any release:
1. `go vet` / `cargo clippy` / `ruff` / `tsc --noEmit` — zero errors
2. Unit tests pass
3. Integration test: install from dist, run `<tool> --version`, run `<tool> --help`
4. Startup time: `time <tool> --version` < 100ms
5. Binary size within declared budget (if applicable)
