## Conventions

- Transform function naming: `transform_{source}_{destination}` (e.g. `transform_raw_orders_normalized`)
- Schema versioning: schemas named with version suffix (e.g. `orders_v2.schema.json`) — never mutate in place
- Idempotency contract: every pipeline run must produce the same output given the same input — enforced by re-run test
- DQ failure handling: failed records go to Dead Letter Queue (DLQ) — never silently dropped
- Null handling: explicit null rate ceiling declared in performance-budgets.md — checked by DQ gate
- SQL files: named after the output table (e.g. `orders_daily_summary.sql`)
