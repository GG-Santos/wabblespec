# Content Types

Audience-specific guidance and defaults for each long-form content type.

## Landing page

**Goal:** Convert visitor to a specific action (sign up, book demo, download).
**Structure:** AIDA (Attention → Interest → Desire → Action) or problem-solution.
**Word count:** 400–800 words for SaaS; up to 2000 for complex products.
**Audience adaptations:**
- Developer: lead with capability, not benefit; include code snippet or API example above the fold
- Business: lead with ROI or time saved; metrics and social proof before features
- End-user: lead with the problem solved; show the product, not describe it

## Blog post

**Goal:** Educate, build authority, drive organic search.
**Structure:** Hook → Context → Body (3–5 main points) → Conclusion + CTA.
**Word count:** 800–2000 words for general topics; 2000–4000 for technical deep dives.
**Audience adaptations:**
- Developer: assume domain knowledge; no need to explain what REST is
- Business: explain "why" before "how"; avoid acronyms without expansion
- End-user: use analogies; test every technical term against "would a non-technical person know this?"

## Technical article

**Goal:** Transfer specific technical knowledge accurately.
**Structure:** Problem definition → Approach → Implementation → Results → Caveats.
**Word count:** 1000–5000 words; no upper limit when completeness requires it.
**Audience adaptations:**
- Developer: precise language required; do not round numbers or simplify mechanics
- All: code examples are mandatory for any implementation claim

## Case study

**Goal:** Prove the product works for a specific use case with a real example.
**Structure:** Customer context → Problem → Solution → Results (quantified) → Quote.
**Word count:** 500–1500 words.
**Required elements:** Quantified before/after metrics; named customer (or anonymized with details); specific timeline.

## Tutorial

**Goal:** Enable the reader to complete a specific task.
**Structure:** Objective statement → Prerequisites → Numbered steps → Verification → Troubleshooting.
**Word count:** as long as required for the task; no target.
**Rules:** Every step is a single action. Steps are numbered, not bulleted. Prerequisites are explicit. The reader knows when they are done.

## Awareness

**Goal:** Make the reader aware of a problem, trend, or category — not necessarily your product.
**Structure:** Problem or trend introduction → Scope → Implications → What comes next (optional soft CTA).
**Word count:** 600–1500 words.
**Rule:** Product mention must be light or absent. Awareness content that reads like a sales pitch fails its goal.
