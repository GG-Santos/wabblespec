# Brainstorm Options — 2026-05-28T10:53:40Z

**Problem:** Skills still manually edit/create receipts, changelogs, VERSION, and other files instead of invoking the Python scripts built to reduce token overhead.

---

## Top 5 Options

### Option 1: Rewrite SKILL.md steps to invoke scripts via Bash
Approach: In every skill that writes receipts, changelogs, or version files, replace prose instructions with explicit `python script.py --args` Bash call sequences.
What it offers: Zero token overhead for structure reasoning — Claude calls the script and moves on.
What it trades off: Every SKILL.md that touches framework artifacts needs a targeted rewrite pass; skills drift again if new ones are authored without this discipline.

### Option 2: Add a shared reference declaring script delegation as mandatory
Approach: Write a `_shared/references/script-delegation-contract.md` listing every standard operation (receipt, version bump, changelog, index) alongside its canonical script call. Route all relevant SKILL.md sections to this reference instead of duplicating prose.
What it offers: Single source of truth; new skill authors inherit the contract without reading every prior skill.
What it trades off: Skills still have to opt in to the routing table — no enforcement at runtime.

### Option 3: Guard layer check detecting manual framework file writes
Approach: Extend Guard's pre-tool-use hook to intercept Edit/Write calls targeting `.wabblespec/CHANGELOG.md`, `.wabblespec/VERSION`, and `state/receipts/*.json`, emitting a COMMAND_RISK warning when the caller is not one of the canonical scripts.
What it offers: Enforcement at execution time — manual writes surface as violations before they land.
What it trades off: Hook complexity increases; false positives possible since scripts write via Python file I/O rather than Claude's Edit tool.

### Option 5: Verifier provenance check validating scripts were invoked
Approach: Add a Verifier gate check (e.g., V-SX: receipt written via receipt-writer.py, not manually) that confirms the canonical scripts ran based on session state or receipt metadata.
What it offers: Execution-time accountability — sessions fail verification if they bypassed scripts.
What it trades off: Requires a `written_by` provenance field in the base receipt schema that currently does not exist.

### Option 6: Archive.py as the sole completion path — prose steps become input-prep only
Approach: Redesign Archive and similar skills so all SKILL.md steps terminate in a single `archive.py` invocation. Prose steps prepare inputs to the script, never write files directly.
What it offers: Scripts become load-bearing, not optional; prose steps cannot substitute for script execution.
What it trades off: Requires rethinking how skills hand off structured reasoning to script CLI args — output format contract work needed.
